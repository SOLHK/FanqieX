# FanqieX 1.78R2 测试版

本版从 `SOLHK/FanqieX` 的 `test` 分支 1.78R1（`b2ebf36`）继续修复。
适配目标为番茄小说 7.4.3 / 7.4.3.33。测试版使用大写 R 并依次递增；正式版经用户确认后才进入 `main`。

## 本轮修复

### 1. 纯图标底栏偶发显示文字

R1 只隐藏 UIButton 的标题子视图，按钮后续自身布局仍能重新显示该标签。
R2 对已成功显示图标的插件按钮暂存并清空各状态的普通、富文本标题；原生分段控件的标题颜色同时保持透明。
保留原入口动作和无障碍名称，切换文字模式时恢复内容，并优先保留宿主后来写入的新标题。
覆盖原生与备用渲染切换、选中/按下、入口变化和标题暂未就绪的情况。稳定布局避免重复改写标题。

### 2. 全集/合集入口与播放进度条重叠

仅在已核对的竖屏播放器控制视图内检查可见全集/合集入口和实际进度控件。
进度控件通过公开视图层级、UISlider 类型或进度视图的运行时类名及尺寸识别；没有猜测或调用未核对的宿主进度 getter。
按转换后的实际坐标，为原生进度拖动区至少预留 40 pt 高度，再与入口的完整点击区域保持 8 pt 间距；更高的原生进度容器也予以保留。
需要让位时优先上移底部信息区域，标题、介绍、全集入口内部间距保持一致。
视频、分页尺寸、进度条及其拖动手势不随之放大或移动。

多次布局从保存的宿主位置计算，不累积偏移；关闭、复用、转为横屏或目标消失时恢复最新宿主位置。
移动后的点击区域必须仍处于各级父视图内。进度控件无法确认、多入口歧义或布局超出支持范围时保留原布局并记录状态。
新增 `dramaControlSpacing178R2` 事件，记录识别状态、进度条和入口坐标及调整量，供真实设备复测。

### 3. 横屏铺满开关无效

旧逻辑采用 Aspect Fit 加背景延展，因此画面仍可能保留左右黑边。
R2 使用播放器原生 Aspect Fill 模式（`scaleMode=2`），按比例放大并裁切溢出部分。
设置名称更新为 **「横屏画面铺满（等比裁切）」**；开启后画面边缘可能被裁切，关闭恢复完整比例。

只改变视频渲染模式和视频画布，不放大播放控件。切集、播放器复用和准备完成后重新应用。
开关即时生效；退出横屏或打开原生侧栏时恢复宿主模式。
`dramaFullscreenMode` 诊断会记录是否真正应用、实际 scaleMode、播放器及窗口尺寸。

## 版本和安装

插件文件名、内部安装标识、设置页、诊断日志及构建报告统一为 **1.78R2**，并重新编译。
此前 R1 对外测试编号对应的旧二进制内部仍为 1.78；本包不是将旧文件改名。

1. 移除旧的 FanqieX / FanqieAdBlock 动态库。
2. 使用 `FanqieX-1.78R2.dylib` 注入原宿主 IPA，再按原流程重签安装。同一宿主只加载一份插件。
3. 在设置或新导出的诊断中确认完整版本号为 1.78R2。

## 验证范围

构建流程包含 Linux 的候选 ARM64 指令回归、二进制结构与签名页检查、异常展开表检查，以及 Xcode 27.2 / iOS 27.2 SDK 的实际插件构建。
云端验证必须匹配同一提交的 Apple 产物、源码哈希和配套汇编，并在通过后打包。以本包 `VERIFICATION.json` 和对应提交 Actions 的实际结果为准。

针对本轮新增按钮后续布局、各状态标题恢复、渲染切换、进度条间距及重复布局、横屏裁切/切集/关闭恢复的回归场景。
自动测试执行候选插件的实际 ARM64 指令，UIKit、Foundation 和宿主对象由明确的边界模型提供；它不等于真实 iPhone 上运行宿主。

用户提供日志的设备系统为 iOS 27.3（24C5037i）。本版仍需在该设备确认最终渲染、触控和宿主进度类识别；不能由构建成功宣称真机问题已全部消除。

## 本轮设备检查

- 打开底栏纯图标，在书城、短剧、书架、我的之间来回切换，并下拉刷新；检查不再出现文字。关闭后确认文字与点击恢复。
- 在图二类型的漫剧中检查全集胶囊与进度条；拖动进度、点击全集后返回，再切下一条。调节底栏尺寸或触发收缩后再检查一次。
- 打开「横屏画面铺满（等比裁切）」进入横屏，检查实际视频铺满；关闭后检查完整画面恢复。连续切集与横竖屏切换后再检查。
- 若仍有异常，请导出 1.78R2 日志，附发生异常的页面截图，以便区分已应用、未匹配和宿主重新布局。
