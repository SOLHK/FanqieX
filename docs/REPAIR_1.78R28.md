# FanqieX 1.78R28 本地测试版

适用番茄小说 7.4.3（7.4.3.33）。本次只修复 R27 插件设置首页空白的根目录判断，功能分组和短剧样式保持 R27 的实现。未推送 GitHub，未触发 CI。

## 空白原因与修复

根目录使用空字符串，原代码却以这个空字符串调用 `NSString hasPrefix:`。该方法对空前缀返回 NO，因此所有分类都被过滤，导航和搜索框可以显示，列表却始终为零行。重建或刷新列表也不能解决这个判断错误。

修复为根目录直接接纳各分类；只有非空子目录才执行路径前缀匹配。

[Apple NSString.hasPrefix 文档](https://developer.apple.com/documentation/foundation/nsstring/hasprefix(_:)) 明确记录了空前缀行为。

## 设置入口

首页只显示大分类，开关与工具逐层进入：

| 功能 | 入口 |
| --- | --- |
| 自动阅读 | 阅读 → 自动阅读 |
| 作者的话、讨论、圈子、礼物等章末净化 | 阅读 → 阅读页面净化 → 章末内容 |
| 去赚更多、听书悬浮、改编剧场 | 阅读 → 阅读页面净化 → 正文与底栏 |
| 书架推荐、时长、导入等净化 | 书架净化 |
| 我的推荐、福利、发帖入口净化 | 我的页面净化 |
| 前台通知与运行期间角标 | 通知管理 |
| 视频导出 | 导出与备份 → 导出当前视频 |

原有配置保留。开启“隐藏”才移除对应内容；自动阅读相关选项默认关闭。视频格式和通知控制范围沿用 R27。

## 验证范围

新回归直接执行最终合并 dylib 内的 `updateRows`、路径处理、排序、属性方法和表格行数方法，外部 Foundation API 是明确的模型边界，其中 `hasPrefix:` 严格采用 Apple 的空前缀行为。R27 成品已在该测试复现首页零行，子目录仍能正常生成。

只重新编译变更的设置菜单文件；其余九个原生目标文件经源码、头文件和既有双构建字节核对后复用，再链接、合并并检查加载结构。最终专项结果及构建信息见包内 `VERIFICATION.json` 和 `verification/`。

当前没有连接 iPhone，未执行真实 UIKit 渲染。这些检查用于验证具体代码缺陷和成品字节，不等同于真机验收。

## 安装

用 ZIP 内唯一的 `FanqieX-1.78R28.dylib` 替换旧插件，重新注入并签名。安装后先检查设置首页的分类列表，再进入阅读、通知管理等子页面。
