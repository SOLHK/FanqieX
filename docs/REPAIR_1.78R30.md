# FanqieX 1.78R30 本地测试版

适用番茄小说 7.4.3（7.4.3.33）。针对 R29 用户反馈中仍未解决的日志导出和详情页玻璃重新修正。已完成的 Telegram 首页入口及全集箭头处理保持原逻辑；未推送 GitHub、未触发 CI。

## 日志导出

R29 用搜索的 `isActive` 判断是否需要关闭搜索。然而搜索可以已经不活跃，却仍占据 `presentedViewController`；原导出处理会在禁用按钮之前直接返回，表现为按钮一直没有变化。

R30 检查实际呈现关系：只有 `presenter.presentedViewController == search` 才从真正的 presenter 关闭搜索，完成后执行原动作。仅残留 presenting 引用而没有实际弹出搜索时，直接执行，不等待不存在的关闭回调。

本次不再用预先填好的方法和动作验证导出。测试执行原始设置入口的方法注册、实际按钮 target/selector 捕获、菜单动作转发、核心导出处理、工作队列和主线程分享回调。R29 在搜索未激活但真实占位时复现无队列；R30 对应状态及另外两个搜索状态均通过。用户观察与该状态表现一致，但当前没有设备内部调用跟踪，不将夹具状态说成已直接捕获的真机原因。

## 详情页玻璃

- 选集与右侧清屏：补上真实 `FQVShortVideoPlayerBottomView`，其旧样式生成截图中的“选集・全N集・免费观看”；R29 适配的是另一组控件。
- 原著章节条：在真实 distribution 相关信息绘制回调后处理“原著・第N章”及章节标题，清除已核实的遮挡层，保留原著箭头和点击动作。
- 返回、更多：即使宿主按钮初始尺寸为零，也先建立固定 36 pt 的玻璃，并用公开居中约束随最终布局定位。原按钮的 frame、约束、target/action 不变，没有全局 UIView/UIButton Hook。

方法归属、ABI、目标视图挂载顺序均对照 7.4.3.33 宿主核对。R29 的真实底栏遗漏、原著条遗漏、零尺寸导航按钮跳过三项负对照已复现；R30 对应专项通过。

## 构建与验证边界

ARM64 iOS 编译、单库链接、加载结构、页哈希、合并启动及容量检查通过。实际回归执行候选 ARM64 指令；Foundation、UIKit、系统队列及 Auto Layout 求解仍是明确的边界模型，没有执行真机像素渲染或真实系统分享面板。

## 安装与检查

用 ZIP 内唯一的 `FanqieX-1.78R30.dylib` 替换 R29，重新注入并签名。

1. 先进入“诊断与其他”点击“导出日志”，检查是否出现系统分享面板。
2. 再进入之前截图的详情播放器，检查返回、更多、原著整条、选集整条及右侧清屏按钮。

最终候选哈希和实际检查结果随包保存在 `VERIFICATION.json`、`verification/`。
