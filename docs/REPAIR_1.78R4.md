# FanqieX 1.78R4 测试版

本版基于 `SOLHK/FanqieX` 的 `test` 分支 1.78R3（`912cf4fb1fe30d1dc5551fc08ddd6d0e756f45bb`），处理悬浮底栏外的黑色底带和纯图标过小的问题。适配目标仍为番茄小说 7.4.3 / 7.4.3.33。

## 本轮修复

### 悬浮底栏外保持透明，画面覆盖到底部

本次 R3 诊断显示，底栏自身的背景与图层背景已经透明，旧背景图和模糊视图也已隐藏；但短剧播放器只有 `440 × 876 pt`，窗口为 `440 × 956 pt`，底栏从 `y=882 pt` 开始。下方约 80 pt 没有视频可显示。同时旧逻辑把短剧列表及圆角图使用的 `#1D1D1D` 背景强制改为黑色。

R4 将这项特定背景绘制改为透明，并恢复有边界的主短剧画布覆盖：只有 `feedType=4`、原始尺寸有效、宽度为原生自动值 0 或匹配屏幕竖向宽度、底部预留在 40–120 pt 范围内时，才将竖向画布补至屏幕底部。由宿主使用同一个尺寸完成分页与播放器布局，不直接设置滚动偏移、不把渲染面移出回收单元，也不修改视频引擎的缩放模式。

控制区单独保留原来的可用高度。仅当宿主请求的是同一完整竖屏画布，才从未改写的原始配置得到控制区高度。已经是原生高度的控制区不再缩短，重复布局不累减；其他 feed、横屏、自定义小画布与不匹配的接口签名保持原布局。关闭液态玻璃后恢复原始尺寸与背景。1.78R3 的全集入口与可见进度轨道 8 pt 间距继续生效。

这与历史 1.76 的处理有关，但不会直接复用旧配置上的缓存 inset；每次均读取当前原生配置，防止切换后沿用旧高度。新增 `floating-canvas-178R4` 诊断记录实际画布、控制区及是否应用，便于实机核验。

### 放大底栏图标

- 默认图标尺寸由 **20 pt 调整为 28 pt**。
- 同时更新 SF Symbols 的配置和实际图标视图大小，保持居中。
- 设置页的图标大小范围扩展为 **16–32 pt**。
- 已明确保存的自定义尺寸继续保留；“恢复底栏默认设置”使用新默认 28 pt。
- 原生分段控件与按钮回退渲染共用同一逻辑，保留原点击路由、纯图标模式的文字抑制和辅助功能名称。

调整入口：**FanqieX 设置 → 底栏外观与尺寸 → 图标大小**。

## 安装

1. 移除旧 FanqieX / FanqieAdBlock 动态库。
2. 注入 `FanqieX-1.78R4.dylib`，按原流程重新签名安装；同一宿主只加载一份插件。
3. 在插件设置或新导出的诊断中确认版本为 **1.78R4**。

本版会实际重新编译。文件名、设置页、诊断版本、Mach-O 版本字及签名标识统一为 1.78R4，不重命名旧二进制。

## 验证范围

构建使用 Xcode 27.2 / iOS 27.2 SDK；验证绑定同一提交的 Apple 产物、源码、配套汇编与审计输入。新增回归执行候选的实际 ARM64 指令，覆盖上传日志中的画布缺口、透明背景、关闭恢复、重复布局、宿主尺寸变化、横竖屏和其他 feed 的隔离、接口签名不匹配时跳过，以及两种底栏渲染器的 28/32 pt 图标布局。

为容纳本轮完整组件，只有 R4 的扩展段上限增加一个 16 KiB 页面至 `0x40000`；旧版本仍受各自原有上限约束。构建器和独立二进制审计同时检查容量、段偏移、签名页和展开表，越界输入继续拒绝。

以对应提交 Actions 和包内 `VERIFICATION.json` 为实际通过记录。自动回归中的 UIKit、Foundation 和宿主接口是显式边界模型，不能替代 iPhone 上的玻璃合成、视频显示和触控验收。

实机重点：底栏外不再出现实色底带；视频覆盖到玻璃胶囊后方；连续切集、查看全集、拖动进度、横屏返回后布局稳定。若曾自定义图标尺寸，可在上述设置入口调到 28 pt。

测试代码继续推送 `test`，正式版经用户确认后才进入 `main`。
